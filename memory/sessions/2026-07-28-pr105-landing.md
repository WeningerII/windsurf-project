## What this session was actually for

The maintainer asked for **a forward-looking plan**, and had asked more than once.
What kept coming back instead was another *status record* — increasingly accurate
descriptions of what was done, when the question was what to do next. That gap is
the reason `docs/WORK_PLAN.md` exists as a separate document from
`docs/MASTER_PLAN.md`: the plan holds decisions and status, the queue holds
ordering, and conflating them is how work got mis-scheduled here before.

## Mistakes worth not repeating

- **Called the 78-record re-tag "mechanical, no risk".** It is not: measured
  against `src/utils/openContentPolicy.ts`, **75 of the 78 would be dropped from
  the product**, because a wrong-edition record is by definition from an edition
  the allowlist does not admit. GAPS §18.5 had already warned this.
- **An adversarial verifier panel fabricated 5 of 20 M&M counterparts (25%).**
  It also produced 7 genuine corrections. Treat a verifier panel as a lead
  generator, not an oracle, and re-verify every figure locally before it reaches
  a document.
- **`git checkout --theirs` clobbered work in `WORK_PLAN.md`** during a lane
  integration. Recovered from `643f9e6`.
- **Truncated `git log` at 20 commits and reported one shelf branch when there
  were three.**
- **Four wrong hypotheses in a row while debugging e2e** (Dock pinning, `toRow`,
  formatter-fed-bad-data, a `useScenes` mount race). Each was ruled out with
  evidence, which is what eventually found the real one.

## The CI tail — three fixes and a defect class

CI had never completed the chain on this branch. `2fd3380` died at
`check:bundle-size`; `3daff1f` was cancelled at 29.5 min by the 30-minute job
timeout mid-e2e (exactly the masking `playwright.config.ts`'s own comment
predicts); `60c3745` failed the last e2e test. Run `30341196839` on `ebc9e7a` is
the first to finish — twelve never-executed gates, all green, including
`check:dead-code`, which had shipped reasoned rather than run because knip OOMs
in this container. Both predicted failure modes were wrong.

The interesting fix is `formatCastingTime`: it read `ct.amount` unguarded while
`loadSpellsForSystem('mam3e')` returns *powers*, which have no casting time, so
the Dock took the whole app into its error boundary. `formatItemCost` had been
written for the identical problem one commit earlier. **Collapsing seven
per-system wrappers into one shared browser moves every runtime shape divergence
onto the shared formatters at once**, and the declared types cannot see it.
Tracked as WORK_PLAN §6.6; recorded in GAPS §20.
